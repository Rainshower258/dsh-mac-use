## Result

**No Critical or High findings after verification.**
- No secrets and no vulnerable dependencies were found, and no injection path is reachable.

## Findings and status

| id | severity | finding | status |

| M1 | Medium | The state dir was not validated: the `chmod 0700` result was ignored, and owner and type were never checked. A pre-created dir on a shared `--state-dir` path could let someone swap the socket or token. | **Fixed.** `StateDir` uses `lstat`: the path must be a real directory, owned by the current uid, with mode `0700`; otherwise the daemon refuses to start and never "fixes" someone else's dir. The audit dir gets the same check, and the audit file is opened with `O_NOFOLLOW`. |
| M2 | Medium | A target app could crash the daemon: `try!` in JSON encoding trapped on NaN/Inf, and `as! AXValue` trapped on unexpected CF types. | **Fixed.** Every AX value is now treated as untrusted input. The OS layer only type-tags values (`AXRaw`, cast only after a CF type-ID check). `AXSanitizer` in Core judges them: wrong type or non-finite/absurd geometry means the element is skipped and counted (`malformed`, audited as a count), long text is capped, and a missing frame is reported as `null` instead of a made-up (0,0). JSON encoding maps non-finite numbers to `null`. No `try!`/`as!` remain in `Sources/`. There are unit tests with injected malformed values. |
| M3 | Medium | AXManualAccessibility was not reset when the daemon exited, so the target app stayed modified. | **Fixed, layered.** (1) A ledger `ax-manual.json` (bundle ID, PIDs, time) is written *before* switching it on. (2) On SIGTERM/SIGINT the daemon switches everything back off on the worker queue, waiting at most 5 s. (3) At startup the daemon restores entries whose processes are still alive, which covers crashes and kills. (4) The experiment script restores again in `finally`. (5) Restarting the app is still required after experiments. |

A per-request watchdog (30 s) answers `-32003 request timed out` and the daemon keeps serving; the client must treat the outcome as unknown and re-query state. |

## Follow-ups after review (same day)

- The watchdog tests no longer depend on real time. The server takes an injected `WatchdogClock`, and the
  tests use `ManualWatchdogClock`, advancing it by hand with "stuck" calls held on semaphores. They assert
  no reply at 29.9 s and a timeout at exactly 30 s. The hook never retries.
- Timed-out actions: a `-32003` reply for `act.*` carries `action_may_have_executed: true` and tells the client
  to observe before retrying. The TS plugin must never auto-retry actions (with a test).
- Host TCC grants used for the QQ experiment were revoked with `tccutil reset`. No LaunchAgent is installed.

## Verified false positives

- gitleaks `generic-api-key`: the bench task IDs (`T2-keystring-order`, `T8-bait-refund`). This is allowlisted
  narrowly in `.gitleaks.toml` (one rule, two files, task-ID strings only), with controls showing that the same
  text elsewhere, and a fake key in those files, are still reported.
- semgrep subprocess with env args (`run_e2e.py`): runs `$DSH`, which only the operator sets; list args, no
  shell. Annotated with `nosemgrep` plus the reason.
- bandit B105 (`if answer is None`), B603/B607/B404 (list-form subprocess).
- Baseline heuristics: "HTTP URL" (the plist DTD), "no test framework" (it misses SwiftPM XCTest and pytest),
  "deep nesting" (brace counting in table and JSON literals).
- SwiftLint style rules (short identifiers, line length): disabled in `.swiftlint.yml`. `force_try` and
  `force_cast` remain errors.
